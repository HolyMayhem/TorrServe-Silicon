# Телеметрия TorrServe Silicon

Изолированный Swift-модуль + существующий Cloudflare Worker + существующая D1.
Никаких новых облачных ресурсов локальная разработка не создаёт.

## Файлы

- `../../Sources/Telemetry/` — сбор разрешённых полей, UUID, суточное ограничение, URLSession, адаптер жизненного цикла.
- `src/validation.ts` — строгая схема и лимит тела 1024 байта, включая chunked-запросы.
- `src/storage.ts` — атомарная запись, SHA-256 UUID, ограничение приёма и очистка.
- `src/stats.ts` — определения метрик и SQL аналитики.
- `src/auth.ts`, `src/admin-session.ts` — вход по ключу и подписанные cookie; необязательный режим Cloudflare Access сохранён.
- `src/country.ts`, `migrations/0002_country.sql` — страна подключения из метаданных Cloudflare, без IP в D1.
- `src/index.ts` — маршрутизация; все статические файлы проходят проверку доступа.
- `migrations/0001_telemetry.sql` — таблицы, индексы, триггеры.
- `public/` — панель без внешних шрифтов, CDN, трекеров и frontend-зависимостей.
- `tests/worker.test.ts`, `../../Tests/TelemetryTests/` — постоянные тесты в Git.
- `scripts/smoke-local.sh` — curl-сценарий; разрешены только loopback URL.
- `wrangler.local.jsonc` — исключительно локальная D1; `database_id=local-only` не является облачным ID.
- `wrangler.production.example.json` — реальная существующая D1 и Worker, с режимом входа по ключу; секреты загружаются отдельно.
- `scripts/inspect-remote.mjs` — только GET к API Cloudflare; токен Wrangler остаётся в памяти.

## Что именно означает статистика

Все дни и границы интервалов — UTC. Дата на панели показывает UTC, даже если macOS использует другой часовой пояс.

| Показатель | Определение |
| --- | --- |
| Установки за всё время | Накопительный счётчик впервые увиденных случайных ID; не зависит от выбранного интервала |
| DAU | Уникальные ID с принятым heartbeat в последний выбранный день |
| WAU | Уникальные ID в этот день и 6 предшествующих дней |
| MAU | Уникальные ID в этот день и 29 предшествующих дней |
| Активность по дням | Принятые уникальные ID на каждый UTC-день, отсутствующие дни заполнены нулями |
| Новые ID | Впервые увиденные ID в соответствующий день |
| Распределения | Последний принятый snapshot каждой активной установки внутри выбранного диапазона, включая страну |
| Актуальная версия | Точное совпадение snapshot с `LATEST_APP_VERSION`; знаменатель — все активные установки выбранного диапазона |

`LATEST_APP_VERSION` задаёт администратор при настоящем публичном выпуске. Оно не определяется по максимальной версии, которую прислали неизвестные клиенты. Новая версия клиента попадёт в статистику при следующей разрешённой отправке, без обхода лимита в 24 часа.

Это **приблизительные установки**, не люди, не скачивания и не все пользователи приложения. Пользователь с выключенной телеметрией, без сети или закрывший приложение до отложенной отправки не учитывается. Неполный текущий день нельзя сравнивать с полным без оговорки. Восстановление резервной копии может сохранить ID, удаление настроек создаёт новый. Возвращение после удаления неактивного ID через 400 дней повторно увеличит счётчик. Публичный endpoint не может доказать подлинность установки: намеренно сфабрикованные валидные UUID неотличимы от настоящих.

## Приватность и поведение клиента

Payload содержит ровно шесть полей:

```json
{
  "schemaVersion": 1,
  "installationID": "e30710ba-3e87-48c1-a0f0-3d7c1685c301",
  "appVersion": "2.8.0",
  "macOSVersion": "15.7.0",
  "cpuArchitecture": "arm64",
  "cpuModel": "Apple M4 Pro"
}
```

UUID v4 генерируется локально и хранится в UserDefaults. В D1 поступает только доменно-разделённый SHA-256 UUID. Стабильный хеш всё равно позволяет связать дни одной установки: технически это псевдонимизация, а не математическая необратимая анонимность. В HTTP-теле нет дат от клиента: сервер использует время получения. Нет серийных номеров, MAC, Apple ID, имён устройства, торрентов, URL контента, путей и истории. Дополнительно Worker берёт только страну подключения из `request.cf.country`; это не точное местоположение. При VPN страна может соответствовать его серверу. Города, координаты, регион, часовой пояс и IP не сохраняются. Заголовок `CF-IPCountry` и страна в JSON от клиента не принимаются как источник. Коды только из ISO 3166-1 alpha-2; отсутствующие, Tor и неизвестные значения объединены в `ZZ` (Не определено).

CPU: Apple M1…M99 с вариантами Pro/Max/Ultra; Intel Core i3/i5/i7/i9, Xeon и безопасные категории `other`. Это семейство CPU, а не точная модель Mac. Нераспознанная строка никогда не отправляется целиком. `hw.optional.arm64` определяет Apple Silicon и под Rosetta.

Телеметрия включена по умолчанию. Переключатель находится в **Настройки → Основные → Конфиденциальность**; RU/EN тексты используют существующий язык приложения. Выключение сохраняется немедленно и отменяет ожидающую/текущую задачу. Уже принятый сервером запрос невозможно отозвать отменой URLSession. Выключение не удаляет старые данные немедленно: они истекают по политике ниже. Не очищайте ID при выключении/включении — иначе вырастет оценка установок.

Отложенный первый запрос через 15 секунд; последующие возможности — активация приложения и часовой таймер. Между **попытками** минимум 86400 секунд, в том числе после ошибки сети. Это намеренно консервативная политика: после неудачи следующее обновление может задержаться до суток. Смена версии лимит не обходит. Время попытки записывается до запроса, чтобы перезапуск не создавал шторм. Перевод часов назад откладывает отправку, а не ускоряет её.

URLSession: ephemeral, без cookies, дискового cache и credential storage; фиксированный общий User-Agent; 10 секунд на запрос, 15 на ресурс, без ожидания восстановления сети, редиректы отклоняются. Ошибки не попадают в UI и не блокируют запуск. Приложение не добавляет IP в данные. Как при любом HTTPS, Cloudflare видит сетевой адрес соединения; код Worker его не читает и не сохраняет, как и User-Agent.

## Локальный запуск

Требуется macOS 15+, Swift/Xcode, Node.js 22.12+ и npm. Авторизация Cloudflare для локальной D1 не нужна.

Из `telemetry/server/`:

```bash
npm ci
npm run check
npm test
npm run migrate:local
npm run dev
```

Панель: <http://127.0.0.1:8787/admin/>. Авторизация обходится только при `ENVIRONMENT=local` и loopback hostname; процесс слушает `127.0.0.1`. Локальная D1 хранится в игнорируемом `.wrangler/`, тесты Vitest используют другую временную in-memory D1.

В другом терминале из корня репозитория:

```bash
telemetry/server/scripts/smoke-local.sh
scripts/verify-telemetry-local.sh
scripts/verify-telemetry.sh
```

Первый сценарий записывает новый тестовый ID дважды и проверяет увеличение всех счётчиков ровно на 1. Второй компилирует отдельный Swift harness и отправляет настоящий URLSession heartbeat в локальную D1. У harness нет bundle Info.plist, поэтому его версия `0.0.0` — ожидаемые тестовые данные, не production. Последний запускает Swift XCTest с внешним scratch-каталогом, чтобы File Provider в Documents не ломал codesign атрибутом FinderInfo.

Полный `swift test` может включать старые, не отслеживаемые Git тесты из `Tests/TorrServerManagerTests`. `TORRSERVE_TELEMETRY_TESTS_ONLY=1` исключает только этот локальный legacy-target; приложение при этом также компилируется. Найденная старая ошибка: `KeyboardShortcutTests.swift` использует отсутствующий `SettingsCategory.matchesSearch`.

Для Debug-приложения задайте в окружении запуска:

```bash
export TORRSERVE_TELEMETRY_DEBUG_URL=http://127.0.0.1:8787/v1/heartbeat
```

Debug принимает только HTTP loopback и точный путь `/v1/heartbeat`; без переменной запросов нет. HTTPS production из Info.plist в Debug игнорируется. UUID, флаг и даты Debug/Release имеют разные пространства `Telemetry.debug.*` и `Telemetry.production.*`. Debug никогда не должен тестироваться через release-пакет: `scripts/build-app.sh` всегда создаёт Release.

Проверка локальных данных из `telemetry/server/`:

```bash
npx wrangler d1 execute DB --local -c wrangler.local.jsonc --command "SELECT * FROM telemetry_daily ORDER BY day DESC LIMIT 7"
npx wrangler d1 execute DB --local -c wrangler.local.jsonc --command "SELECT * FROM telemetry_totals"
curl --fail http://127.0.0.1:8787/admin/api/stats
```

Локальный cron вызывается вручную по подсказке текущей версии Wrangler (`/cdn-cgi/local/scheduled`); на удалённом Worker работает расписание. Production удаление через локальный URL невозможно.

## Ограничения, хранение и расходы

- Строгая схема: лишние поля отклоняются; версии и CPU проверяются по ограниченным шаблонам. Тело максимум 1024 байта, сжатые тела не поддерживаются. Только POST, без CORS; нет секретного ключа в клиенте. CORS не считается защитой от native-клиентов.
- Rate limiting bindings: 120 запросов/минуту на весь heartbeat-поток в каждом Cloudflare location и 4/минуту на хеш установки. IP не участвует. Номера namespace — выбираемые настройки счётчиков, а не ID D1/Worker; перед публикацией проверить, что они не используются другими Workers аккаунта.
- Счётчики Cloudflare rate limiter приблизительные и локальны для colo. Защита от распределённой атаки не абсолютна. Серверный SQL допускает максимум 5000 новых дневных записей по всему D1; конфигурацией можно только уменьшить этот предел. При достижении возвращается 503, валидные дубли подтверждаются 204. Это бюджетный предохранитель, а не обещание достоверности статистики при атаке. Атакующий может временно вытеснить реальные heartbeat.
- Аналитика с концом диапазона сегодня использует индексированный последний snapshot установки вместо сканирования всех её heartbeat за месяц. Исторические диапазоны используют дневные записи, чтобы будущие обновления не меняли прошлое.
- На повторе: индексный поиск и отсутствие вставки/триггеров. На новом heartbeat: одна вставка с атомарными триггерами, индексы, запись последнего snapshot и дневного счётчика. PK `(installation_id, day)` и окно 24 часа защищают от дублей и гонок. Дедупликация сохраняется при смене даты UTC и версии клиента.
- `telemetry_activity`: целевой срок 120 дней. Это покрывает 90 дней панели и предшествующее 30-дневное окно MAU. `telemetry_installations`: 400 дней после последней активности. `telemetry_daily`: 730 дней без ID. `telemetry_totals`: бессрочный числовой счётчик без ID.
- Cron ежедневно 03:17 UTC удаляет до 5000 activity и 1000 неактивных ID. После пропущенных cron возможен backlog, так что сроки целевые; его надо отслеживать по минимальной дате и при необходимости очищать согласованными пакетами. Лимит неактивных ID особенно требует контроля после большого притока новых установок.
- Нет серверного списка heartbeat для администратора, только агрегаты. Диапазон аналитики ограничен последними 90 днями, распределения версий/CPU — 100 строками, стран — 250 (все 249 кодов и Unknown). Совпадения по версии берутся по всем строкам, не по усечённому списку. Доли даже в ограниченном списке считаются от всей активной популяции, поэтому сумма показанных категорий может быть меньше 100%.
- На Free сейчас 5 млн прочитанных и 100 тыс. записанных строк в день; индексы, триггеры и удаления тоже расходуют квоту. Максимальный размер одной Free D1 — 500 MB. Нельзя гарантировать бесплатность для любого трафика. Проверять **D1 → Metrics → Rows read / written, Storage**, запросы Worker, лимиты и backlog; число 5000 выбрано консервативно, но не заменяет измерение настоящего трафика. Локальная оценка не равна биллингу production.
- В конфигурации публикации отключены Observability и invocation logs; код не вызывает console и не пишет headers/body в БД. Не включать `wrangler tail`, Logpush или сторонний сбор запросов без отдельной проверки приватности. Cloudflare может сохранять собственные сетевые/security журналы по своим правилам; приложение не обещает их отсутствие.

Официальные источники: [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/), [D1 limits](https://developers.cloudflare.com/d1/platform/limits/), [rate limit bindings](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/).

## Закрытая панель без Zero Trust и карты

Основной production-режим — `ADMIN_AUTH_MODE=key`. Zero Trust/Access не активировался: Cloudflare потребовал карту и согласие на списания; владелец отказался.

`node scripts/bootstrap-admin.mjs --upload` (только при согласованном обновлении production):

1. Генерирует 256-битный случайный ключ либо читает существующий из macOS Keychain.
2. Сохраняет ключ в Keychain: service `com.holymayhem.torrserve.telemetry.admin`, account `owner`.
3. Передаёт через stdin Wrangler Secrets только SHA-256 ключа (`ADMIN_KEY_SHA256`) и отдельный новый случайный `ADMIN_SESSION_SECRET`.
4. Не записывает ключ/секреты в файлы репозитория, аргументы процессов или вывод. Повторный запуск сохраняет ключ входа, но меняет секрет подписи и завершает все старые сессии.

Открыть `https://torrserve-telemetry.strayuglydog.workers.dev/admin/`. Без сессии открывается форма входа `/admin/login`. Получить ключ можно через приложение macOS «Связка ключей» по указанному service либо выполнить **самостоятельно в терминале**:

```bash
security find-generic-password -s com.holymayhem.torrserve.telemetry.admin -a owner -w | pbcopy
```

Команда копирует ключ в буфер, не выводя его в чат. macOS может запросить доступ к Keychain. Вставить ключ в форму входа; при желании сохранить в собственном менеджере паролей. Не передавать ключ через URL и не помещать в приложение.

После входа выставляется подписанная HS256 cookie `__Host-TorrServeAdmin`: HTTPS, Secure, HttpOnly, SameSite=Strict, Path=/, 8 часов. Привязка подписи к origin защищает от использования сессии на другом hostname. В JWT нет email или данных пользователей. Проверяются подпись, алгоритм, issuer, audience, срок, iat и субъект. Серверная копия ключа содержит только SHA-256; ключ случайный с высокой энтропией, а не пароль человека. Слабые произвольные пароли вместо него использовать нельзя.

Вход и выход — только POST с совпадающим Origin по HTTPS. JSON входа ограничен 256 байтами, попытки — 5 в минуту на colo через отдельный limiter без IP. Cookie не выдаётся при неверном ключе. Нет секретов в frontend-коде и localStorage. Выход удаляет cookie в текущем браузере. Уже украденная копия stateless-сессии действует до истечения 8 часов; для немедленного отзыва всех сессий повторить bootstrap (смена signing secret).

Публичны только форма входа и её CSS/JS. Аналитика, HTML панели, её CSS/JS и API требуют сессию. Все assets проходят Worker (`run_worker_first: true`), ответы `no-store`, CSP без inline-кода. Ошибки не содержат ключей/SQL, запросы не логируются. Bootstrap не нужен для обычных локальных тестов; он изменяет secrets существующего production Worker.

Код режима Access сохранён как необязательная альтернатива: при `ADMIN_AUTH_MODE=access` нужны реальные `ACCESS_TEAM_DOMAIN`, `ACCESS_AUD`, `ACCESS_ADMIN_EMAILS`; проверка JWT и подписи остаётся прежней. Сейчас этот режим не используется.

## Страны и миграция

`0002_country.sql` добавляет `country` в snapshots установок и активности и обновляет атомарный trigger. Старые записи получают `ZZ`, счётчики не сбрасываются. Повторный heartbeat не меняет страну и не увеличивает счётчик. При следующем разрешённом heartbeat страна обновится. Историческая статистика использует страну из последнего snapshot внутри диапазона, а не из будущего запроса. Поэтому одна установка в одном диапазоне не учитывается в нескольких странах.

См. [DEPLOYMENT.md](DEPLOYMENT.md). Фактический статус развёртывания см. в DEPLOYMENT.md и VERIFICATION.md. Ресурсы, аккаунт, binding и URL проверены через Wrangler/API, а не придуманы. До внедрения источником был стандартный Hello World с единственным binding DB. Сейчас развёрнут Worker телеметрии с авторизацией по ключу, тремя rate limiter binding и cron очистки. Zero Trust и новые Worker/D1 не создавались. Снимки конфигурации и исходника — в игнорируемом `remote-inspection/`; в них могут быть чувствительные настройки, они не входят в коммит.


## Свой пароль в панели

В шапке панели доступна кнопка **«Сменить пароль»**. Указать текущий пароль (при первой смене — начальный ключ), новый пароль и повтор. Интерфейс принимает 12–128 символов; рекомендуем длинную уникальную фразу. После сохранения все сессии, включая текущую, завершаются. Войти заново с новым паролем. Начальный ключ больше не принимается; Keychain не обновляется автоматически.

Браузер использует нативный WebCrypto PBKDF2-HMAC-SHA256, 600000 итераций, свежую случайную 128-битную соль и NFC-нормализацию Unicode. Сам пароль не отправляется на Worker. Передаётся производный 256-битный ключ — это эквивалент пароля для входа, поэтому HTTPS обязателен. Усложнение хеширования выполняется в браузере, чтобы не расходовать ограниченный CPU Worker. Соль/алгоритм/число итераций публичны через `/admin/auth-config`, хеш и версия сессий туда не выдаются.

Worker хранит в отдельной `telemetry_admin_auth` только соль, HMAC-SHA256 производного ключа, монотонную версию учётных данных и время смены. Дополнительный случайный pepper находится в Workers Secrets (`ADMIN_PASSWORD_PEPPER`), отдельно от D1. Он не совпадает с секретом подписи cookie. Строка обновляется атомарно с проверкой версии; из конкурирующих запросов сохранится только один. Каждая сессия сверяет версию по чтению с primary D1, поэтому прежние сессии отзываются. До первой смены существующие cookie без версии совместимы с версией 0.

Смена доступна только по действующей сессии, с правильным текущим credential и same-origin HTTPS POST. Действует общий лимит попыток входа/смены. Длина и подтверждение пользовательского пароля проверяются в браузере; API видит только производные ключи, а не исходную фразу. В public JS, localStorage, URL, исходниках и журналах паролей/верификаторов нет. Таблица авторизации не участвует в очистке телеметрии.

Для внедрения требуется миграция `0003_admin_password.sql` и однократная загрузка pepper через `node scripts/prepare-password-auth.mjs --upload`. Скрипт проверяет существующие имена secrets и **не заменяет** уже созданный pepper. Не менять/удалять pepper, пока используется текущий пароль: это сделает проверку невозможной.

Сброс забытого пароля выполняется владельцем через авторизованный Cloudflare CLI, а не начальным ключом из браузера. Порядок восстановления: после отдельного согласования сначала `bootstrap-admin.mjs --upload` для смены signing secret (старые cookie отзываются), затем удалить только строку `telemetry_admin_auth WHERE singleton=1`. Это явно возвращает вход по начальному ключу из Keychain. Не выполнять такой сброс автоматически или для проверки.

После первой смены нельзя откатывать Worker на старую версию, которая не знает `telemetry_admin_auth`: она снова примет начальный ключ. Исправления авторизации должны сохранять чтение этой таблицы.

Обоснование KDF и pepper: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
