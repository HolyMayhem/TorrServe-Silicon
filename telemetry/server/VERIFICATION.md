## Ограничения проверки

- Полный старый локальный набор `Tests/TorrServerManagerTests` не проходит компиляцию: `KeyboardShortcutTests.swift:37–40` обращается к отсутствующему `SettingsCategory.matchesSearch`. Эти файлы были игнорируемыми до задачи и не изменялись. Отдельный telemetry-target проходит; полная Release-сборка проходит.
- Первоначальный запуск XCTest внутри Documents столкнулся с FinderInfo/resource fork при codesign. Внешний scratch-каталог `/tmp` устраняет проблему без изменения исходников или настроек подписи приложения.
- Физический Intel Mac и запуск приложения под Rosetta не проверялись. Есть cross-compile и тесты Intel-ветвей; они не заменяют hardware smoke.
- Новая секция настроек скомпилирована и использует существующие компоненты; live-проверка приложения ещё нужна. Тесты не доказывают внешний вид нативного SwiftUI.
- Узкая панель проверена через изменение CSS viewport масштабированием Safari; это не тест на физическом телефоне. Отдельные мобильные браузеры перед релизом ещё проверить.
- Cloudflare Access не используется: Zero Trust требовал карту и согласие на списания, владелец отказался. Работает вход по случайному ключу и Secure / HttpOnly cookie. Реальный протокол проверен через HTTPS/CLI; новый экран входа и добавленная карточка стран визуально пока не проверялись, Computer Use использовался только для отменённой настройки Access.
- Проверен настоящий D1 SELECT: rows_written=0, размер после миграций 49152 bytes. Это не нагрузочная оценка: фактические квоты и backlog следует контролировать после появления пользователей.
- Тестовые UUID и snapshots существуют только в локальной D1; в production тестовая телеметрия не отправлялась.

### Ограничения и публикация

- Физический Intel Mac и мобильные браузеры не проверялись. Поставляемая app — arm64; Intel-проверка относится к изолированному модулю Telemetry.
- Сохраняется принятая проектом ad-hoc подпись без notarization. Это существующая модель распространения, а не новая регрессия.
- Локальная лента проверяет реальную установку Sparkle и точный подписанный архив. Доступность будущего публичного URL DMG проверяется уже при публикации, до обновления публичного appcast.

Ранее заблокированные проверки Sparkle и нативного переключателя завершены. Для выпуска осталось согласовать публикацию точного артефакта, создать release/tag v2.9.0, опубликовать DMG, проверить URL, затем опубликовать appcast. Синхронизацию серверного LATEST_APP_VERSION=2.9.0 выполнить подтверждённым обновлением существующего Worker; миграций D1 для этого не требуется.
