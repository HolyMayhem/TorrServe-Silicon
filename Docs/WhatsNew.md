# Как выпускать сообщения «Что нового»

Содержание: **Resources/WhatsNew.json**. Код окна менять для каждого релиза не нужно.
Сейчас автопоказ **выключен**, предпросмотр работает.

## Релиз с нововведениями

1. Обновите версию приложения в `Resources/Info.plist` как обычно:
   `CFBundleShortVersionString` — версия для пользователя, `CFBundleVersion` — номер
   сборки (положительное целое число).
2. В `Resources/WhatsNew.json` укажите:
   - `enabled: true`;
   - `build`: точно такой же номер, как `CFBundleVersion`;
   - новый уникальный `id`, например `interface-refresh-2-9`.
3. Заполните `localizations.ru` и `localizations.en`: заголовок, текст кнопок и
   `features`. У пункта есть `symbol` (название SF Symbol), `title` и `body`.
   Лучше 2–4 коротких пункта; поддерживается 1–6, длинный список прокручивается.
4. В `detailsURL` укажите HTTPS-ссылку на полный список изменений конкретного релиза.
   Если ссылка не нужна, установите `null` — вторичной кнопки не будет.
5. Соберите `.app`: `./scripts/build-app.sh`, проверьте предпросмотр и публикуйте
   обновление обычным способом через Sparkle.

Пример полей для **условной** сборки 42:

```json
"id": "interface-refresh-2-9",
"enabled": true,
"build": 42
```

Номер версии в окне берётся из `.app` автоматически; в текстах дублировать его не надо.

## Фикс без объявления

Поставьте **`"enabled": false`** перед сборкой. Тексты можно оставить для предпросмотра.
Смена версии сама по себе не открывает окно. Если забыть поменять `build` у включённого
объявления, сборочный скрипт остановится с ошибкой, вместо выпуска неправильного окна.

## Когда окно появляется

После обновления, при первом открытии главного окна, если для этой сборки включён
показ и `id` ещё не просмотрен. Закрывается кнопкой **«Продолжить»** (или Return),
после чего этот `id` запоминается. Стандартных кнопок окна и закрытия через ⌘W нет.
Если выйти из приложения до «Продолжить», сообщение останется до следующего запуска.
При пропуске версий показывается только объявление текущей сборки.

На свежей установке автопоказа нет. Для перехода со старых версий без истории запуска
используются сохранённые настройки приложения/Sparkle как признак прежней установки.
История хранится локально в UserDefaults (`WhatsNew.*`), сервер не требуется.

## Проверка перед выпуском

**TorrServe → Show Developer Menu → Настройки → Разработчик → Окно «Что нового» →
Показать предпросмотр.** Он работает и при `enabled: false`, не меняет историю показов.
Изменив JSON, пересоберите и перезапустите `.app`, чтобы обновить ресурс внутри неё. При запуске одного
SwiftPM-executable без сборки `.app` ресурс не подхватывается из исходников.

Проверки: `./scripts/verify-whats-new.sh`, `./scripts/verify-whats-new-ui.sh` (Mac с Xcode).
Они также запускаются в macOS CI. Для ручного теста автопоказа используйте отдельную
тестовую установку: сначала сборку с выключенным сообщением, затем более высокую
сборку с включённым. Системные уведомления macOS к этому окну отношения не имеют.
