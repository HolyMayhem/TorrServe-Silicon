# Поиск настроек

Индекс строится из названий реальных строк и групп SwiftUI. Отдельного словаря
ключевых слов нет. При непустом запросе страницы создаются в режиме индексации:
общие компоненты публикуют названия через PreferenceKey, не создавая редакторы
и кнопки строк. Обработчики появления страниц и загрузка истории не запускаются.
Индекс существует только пока открыт поиск и обновляется вместе с моделью и языком.
Значения полей, пути пользователя и ключи API в индекс не попадают.

`settingRow`, `toggleRow`, `menuBarToggleRow`, `notificationPreferenceRow`,
`settingSlider`, строки сочетаний клавиш и `ServerSettingsGroup` уже подключены.
Новая настройка на этих компонентах автоматически появляется в поиске. Не нужно
менять SettingsSearchIndex или SettingsWindowView. Новая категория перечисляется
через SettingsCategory.allCases; маршрутизация её формы остаётся обычной задачей UI.

Для нового нестандартного компонента добавьте `.searchableSetting(title)` на строку
и используйте тот же `title`, который показываете пользователю. Пример:

```swift
HStack {
    Text(title)
    Spacer()
    CustomControl()
}
.searchableSetting(title)
```

Модификатор задаёт стабильный адрес (категория, группа, название), записывает
название в индекс, подсвечивает цель перехода и отключает построение редактора
в режиме индексации. Названия строк внутри одной группы должны быть уникальны.
Группы регистрируются через `.searchableSettingsGroup(title)`; стандартный
ServerSettingsGroup делает это сам.

Ищутся названия доступных при текущем состоянии строк и групп, включая отключённые
контролы. Если условие вообще убирает настройку из формы (например, собственные API
ключи при выборе встроенных), она не индексируется. Поиск не меняет состояние
приложения, чтобы искусственно показать такую строку. Текст подсказок и значения
контролов не используются как поисковые названия.

Для раскрывающегося блока его содержимое должно создаваться при индексации
без DisclosureGroup. `settingsSearchRevealSection` сохраняет идентификатор блока
в результате; страница раскрывает его перед переходом. Такой пример — диагностика
в MainWindowView. Новые строки внутри этого блока подключаются общими компонентами.

Прокрутка работает через ScrollViewReader после появления адреса в preferences;
повторный выбор того же результата создаёт новую ревизию перехода. При включённом
уменьшении движения анимация не используется. Очистка запроса снимает подсветку.

Проверка алгоритма: `./scripts/verify-settings-search.sh` (нужен Swift compiler).
Она проверяет нормализацию, ё/е, порядок слов, совпадения, ранжирование, дубликаты,
новую настройку и повторный переход. Нативную прокрутку, сбор индекса SwiftUI,
фокус поля поиска и раскрытие блока нужно проверить запуском приложения на macOS.
