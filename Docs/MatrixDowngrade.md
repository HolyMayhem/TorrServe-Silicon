# Даунгрейд MatriX для проверки обновлений

1. В меню приложения выберите **Show Developer Menu**.
2. В настройках «Разработчик» откройте блок **Даунгрейд MatriX**.
3. Нажмите **Найти старые версии**. Приложение прочитает `--version` выбранного
   исполняемого файла и запросит последние 100 официальных релизов YouROK/TorrServer.
   В список попадут только более старые стабильные релизы с Darwin ARM64 asset.
4. Выберите версию (по умолчанию ближайшую более старую) и нажмите
   **Выполнить даунгрейд…**, затем подтвердите установку выбранной версии.
5. После успешной замены используйте обычное обновление из сайдбара или раздела
   «Обновления». Выполняется реальная проверка версии выбранного бинарника.

## Замена исполняемого файла

Скачивается конкретный release tag, а не latest. Ответ GitHub должен содержать
ровно выбранный tag. Используется общий загрузчик с прежними проверками HTTP,
размера, Mach-O/ARM64, SHA-256 (когда GitHub сообщает digest) и `--version`.
Повторно проверяется, что выбранная версия старее актуального исполняемого файла.

Физически предыдущий файл не перезаписывается: новая версия сохраняется в отдельную
папку Versions и становится выбранным исполняемым файлом. Это также позволяет
работать с bundled-бинарником без изменения подписанного .app bundle.

Если сервер работал, общий TorrServerUpdateInstaller приостанавливает загрузки,
останавливает сервер, переключает путь и проверяет запуск/здоровье старой версии.
При ошибке он возвращает прежний путь и пытается запустить прежний сервер. Ошибка
отката явно показывается. Если сервер был остановлен, он остаётся остановленным;
перед выбором бинарник уже проходит проверку версии.

Перезапуск прерывает воспроизведение. Старая версия использует существующий каталог
данных сервера. Откат исполняемого файла не является резервной копией данных или
откатом изменений формата базы, которые могла сделать старая версия.

## Автообновления

После успешного даунгрейда включается флаг тестового режима только в текущем сеансе.
Обнаружение обновлений и ручная установка работают обычным путём. Автоустановка
временно пропускается, иначе она сразу отменит даунгрейд. Пользовательская настройка
автообновлений в UserDefaults не изменяется.

Тестовый режим снимается при успешном обычном обновлении/загрузке latest,
нажатии «Завершить проверку» или перезапуске приложения. «Завершить проверку»
возвращает обычное поведение: если автообновления включены, свежая версия может
установиться автоматически. Статус паузы виден и в developer-разделе, и в «Обновления».

Поиск/закрытие developer-раздела сами не скачивают и не меняют исполняемые файлы.
Одновременные операции установки блокируются. Во время передачи используется
обычная индикация прогресса; проверка обновлений, начатая до операции, инвалидируется.

## Проверки

`./scripts/verify-matrix-downgrade.sh` (на Mac с Xcode) проверяет:
- числовое сравнение версий и фильтрацию каталога (старые/новые, draft/prerelease,
  архитектура, размер, дубликаты, пустой и некорректный JSON);
- паузу/возобновление автоматической установки и сохранение обычной политики;
- выбор без запуска для остановленного сервера, перезапуск работающего,
  восстановление предыдущего пути/процесса, сообщение об ошибке самого отката;
- запрос конкретного тега и отказ при несовпадении ответа GitHub через URLProtocol.

Тесты используют фикстуры и имитацию процессов, не меняют реальный TorrServer
и не запускают сетевое скачивание бинарника.

В Linux проверены синтаксис исходников Swift/bash, git diff --check и реальный
формат публичного GitHub API (доступны старые Darwin ARM64 релизы). Сборка,
исполнение Swift-проверок, реальный даунгрейд и последующее обновление на macOS
в этой среде не проверялись.
